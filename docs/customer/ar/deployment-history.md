# البناء وإعادة Deployment ومراجعة السجل

تابع مراحل البناء ومصدر الطلب والنتيجة وسياسة الاحتفاظ.

تاريخ المراجعة: 2026-10-05

## مسار Deployment

قد يبدأ Deployment من الإطلاق الأول أو Webhook لدفع Git أو طلب يدوي أو دمج أو تراجع. يتطلب الدفع التلقائي Webhook يعمل لدى المزوّد وفرعًا مطابقًا للمستودع. إذا لم يظهر الدفع، راجع تسليم Webhook لدى المزوّد. تتطلب إعادة Deployment اليدوية دور **مسؤول Deployment**.

| المرحلة | ما الذي يجري؟ |
| --- | --- |
| Queued | انتظار مكان للبناء أو اكتمال العمل المتعارض. |
| Building image | جلب الكود والتحقق من المتطلبات وتجهيز صورة التشغيل. |
| Upgrading modules & rolling out | تطبيق تحديثات Odoo اللازمة والتحقق من تشغيل النسخة الجديدة. |
| Success / Failed | النتيجة النهائية؛ راجع التفاصيل قبل إجراء تغيير آخر. |

## مراجعة عملية البناء

اختر البيئة وافتح سجل Deployment. راجع المصدر والفرع وCommit والكاتب والوقت والمرحلة والنتيجة. يتيح **قارئ المشروع** عرض بيانات البناء، بينما تتطلب مخرجاته دور **قارئ السجلات**. تستمر الصورة الحالية في خدمة الطلبات أثناء التجهيز عندما يكون ذلك ممكنًا، لكن التشغيل الجديد وتغييرات القاعدة قد تؤثر على المستخدمين.

## الاحتفاظ بالسجل

الاحتفاظ بالسجل محدود وليس دائمًا. الإعداد الافتراضي 30 يومًا و50 سجلًا مكتملًا لكل بيئة، ويمكن للمنصة تعديله. قد تُحمى العمليات الجارية والصورتان الحالـية والسابقة الناجحتان وبيانات أساس التحديث من التنظيف المعتاد. احفظ مخرجات الأخطاء المهمة قبل حذفها؛ فالاحتفاظ بسجل البناء مستقل عن النسخ الاحتياطية وصور Registry.
