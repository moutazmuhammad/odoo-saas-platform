# نظرة عامة على الفريق والصلاحيات

افهم الملكية والجهات الممنوحة والأدوار والوصول بالقدر المطلوب.

تاريخ المراجعة: 2026-10-05

## نموذج الوصول

يجمع منح الوصول عضوًا أو مجموعة، ومشروعًا أو عدة مشاريع للعميل نفسه، ودورًا ثابتًا أو عدة أدوار، ونطاق Production أو Staging أو Development أو كل البيئات. تتكامل الأدوار داخل نطاقاتها. لا ينشئ العملاء أدوارًا مخصصة، ولا توجد مجلدات أو هياكل مؤسسات يحتاجون إلى ضبطها.

## المالك وعضو الفريق

يحتفظ مالك حساب العميل بالتحكم في المشروع والفوترة. يحصل أعضاء الفريق على صلاحيات صريحة للمشاريع؛ ولا يمنح أي دور فواتير المالك أو محفظته أو الشراء أو مدير قواعد البيانات غير المقيّد. يستطيع عضو الفريق امتلاك مشاريع مستقلة بعد اكتمال إعداد حسابه، وتظل المشاريع المشتركة خاضعة لأدواره. صلاحيات VELTNEX لا تنشئ مستخدمي تطبيق Odoo ولا تستبدل صلاحياته.

## مثال

لعضو يتابع الإصدارات، امنح قارئ المشروع وقارئ السجلات ومسؤول Deployment على المشاريع المطلوبة في Staging وDevelopment. يستطيع مراجعة هذه البيئات ونشرها دون النشر إلى Production أو فتح Shell أو حذف القواعد أو إدارة الفوترة.
