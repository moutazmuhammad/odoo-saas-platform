# ربط مستودع Git

اضبط كود المشروع واعتماد المستودع الخاص وتوارث الفروع.

تاريخ المراجعة: 2026-10-05

## قبل البدء

هذه خاصية للاستضافة. يتطلب ضبط المستودع دور **مدير المشروع** أو حساب المالك وInstance تعمل أو متوقفة. يستطيع مسؤول Deployment نشر الإعداد الموجود، لكنه لا يغيّر إعدادات مستودع المشروع. تختلف صلاحيات المزوّد وسلوك API بين GitHub وGitLab وBitbucket وتكاملات Gitea المدعومة.

## الربط وDeployment

1. في Production، افتح **الكود والحزم** وأدخل عنوان استنساخ Git واسم الفرع.
2. للمستودع الخاص، أدخل Token يملك الوصول إليه، مع السماح بعمليات الفروع وWebhooks إذا كنت ستستخدمها.
3. اختر **ربط وDeployment** أو **حفظ وإعادة Deployment**، وانتظر نتيجة البناء والتشغيل.
4. عند تعديل الإعداد لاحقًا، يحافظ ترك Token فارغًا على القيمة المحفوظة. لا تنشر الاعتمادات في بلاغ عام أو مقتطف سجل.

## التوارث وفصل المستودع

ترث البيئات التابعة المستودع واعتماده من المشروع مع الفرع المختار لكل بيئة. تُدار إعدادات الاتصال المشتركة في Production. فصل المستودع يزيل الكود المخصص من صورة التشغيل، لكنه لا يلغي تثبيت وحداته في قواعد البيانات. قد تظل الوحدات المثبتة بحاجة إلى الكود؛ لذا خطّط للفصل واختبر أثره بعناية.
