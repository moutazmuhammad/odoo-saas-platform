# فهم تحديث وحدات Odoo بشكل انتقائي

ميّز بين Deployment للكود وتحديث الوحدات والانتقال إلى إصدار رئيسي جديد.

تاريخ المراجعة: 2026-10-05

## كيف تُختار الوحدات؟

يقارن البناء المدخلات المؤثرة في تحديث وحدات المستودع بآخر أساس ناجح. تشمل هذه المدخلات الإصدار والاعتماديات والبيانات المحمّلة في Manifest، وحقول النماذج وتعريفات البنية، وملفات XML أو CSV المحمّلة، وملفات الترحيل. عادةً لا يستدعي تغيير منطق دالة Python أو الملفات الثابتة تحديث قاعدة البيانات وحده.

تُمرر أسماء وحدات المستودع المختارة دون طلب التحديث الشامل `all`. عند غياب أساس سابق قد تُختار كل وحدات المستودع المكتشفة. يتجاوز Odoo الوحدات غير المثبتة؛ لذا لا يحل Deployment محل تثبيت تطبيق جديد. وقد تؤدي اعتماديات Odoo ومنطق الترحيل إلى أعمال إضافية مرتبطة بالقاعدة.

## طلب تحديث يدوي

1. انسخ قاعدة البيانات احتياطيًا وتأكد من وصول كود الوحدات إلى البيئة.
2. من قواعد البيانات اختر إجراء تحديث الوحدات للقاعدة المطلوبة.
3. أدخل أسماء الوحدات التقنية صراحة مثل `sale, stock_account`. استخدم صلاحية **مسؤول Deployment** وتابع تقرير العملية.

> تنبيه: قد يغيّر تحديث الوحدات بنية القاعدة والسجلات. وهو مستقل عن تغيير إصدار Odoo الرئيسي، وينبغي اختباره في Staging قبل Production.
