# معالجة Deployment البطيء أو المخفق

ميّز انتظار البناء وإخفاق الحزم وأخطاء الوحدات ومشكلات التشغيل.

تاريخ المراجعة: 2026-10-05

## التشخيص حسب المرحلة

| العَرَض | ما الذي تراجعه؟ |
| --- | --- |
| انتظار طويل | عملية متعارضة أو سعة بناء محدودة. تواصل مع الدعم إذا لم يظهر تقدم. |
| إخفاق جلب المستودع | عنوان الاستنساخ ووجود الفرع ووصول Token واتصال المزوّد. |
| إخفاق بناء الحزم | requirements.txt وتوافق الإصدارات وأول خطأ تثبيت مرتبط. |
| إخفاق تحديث وحدة | الوحدات المحددة والاعتماديات المفقودة ومخرجات الترحيل وإعادة المشكلة في Staging. |
| التشغيل الجديد غير جاهز | سجلات بدء التطبيق وتوافق الصورة ووصول القاعدة وضغط الموارد. |
| دفع Git لا ينفّذ Deployment | تسليم Webhook والفرع المطابق وتكامل المستودع وسجل البناء الموجود. |

## لماذا تختلف المدة؟

تستخدم المنصة طبقات متطلبات مخزّنة مؤقتًا واختيار الوحدات المتغيرة ومتابعة البناء في الخلفية. قد تطول المدة عند غياب Cache أو إضافة حزم Python أو نقل الصور أو ازدحام قائمة العمل أو ترحيل القاعدة. تجنّب إعادة Deployment المتكرر لنفس Commit المخفق. أصلح السبب ثم أعد الطلب مرة واحدة، وراجع التراجع والاستعادة إذا تأثرت الخدمة الفعلية.

## أخطاء اتصال الإشعارات المباشرة

يتطلب خطأ websocket أو longpolling في سجلات Odoo عادةً مراجعة توجيه المنصة الخاص بالإصدار وخدمة التطبيق للأحداث. تستخدم Odoo 16 والأحدث /websocket، بينما تستخدم Odoo 15 والأقدم /longpolling. أرسل للدعم إصدار Odoo والبيئة والخطأ كما ظهر. لا تغيّر قاعدة التطبيق أو تعطّل ضوابط الوصول لتجاوز مشكلة التوجيه.
